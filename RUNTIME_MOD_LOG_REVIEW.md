## Movement-speed review

`FastWalkNoRestrictions150.reds` is present in the compiled source list and
owns the only player-wide 2.5x `MaxSpeed` modifier. No other active source
modifies player `MaxSpeed`; Black Chrome's `MaxSpeed` records apply only to
equipped cyberware. The earlier implementation applied the transient player
modifier only at attach/resurrection, leaving a save-load/equipment-refresh
race where the stat container could rebuild and silently discard it.

That race is now closed without a per-frame poll: the modifier is guarded for
missing stats/invalid IDs, re-added remove-first (idempotent, never stacking),
and re-applied once 0.25 seconds after attach, save attachment, or
resurrection. The forced-walk and SceneTierII hooks remain unchanged. A 2.5x
multiplier should put sprint near the engine's approximately 15 m/s on-foot
ceiling (vehicle-like travel, not actual vehicle physics). This
proves the intended source logic and removes the likely overwrite path, but a
manual in-game traversal is still required to measure actual movement speed;
the available logs contain no player-velocity telemetry.

### Cyberware function-text regression (2026-10-26 compile-only fix)

The user's symptom—vanilla and Black Chrome implants showing stats and lore
but no effect/function paragraphs—was traced to the source, not to missing
English localization. `UIInventoryItemModsManager.Make()` first calls the
vanilla `FetchModsDataPackages()` routine, which places each cyberware
`OnEquip`/`OnAttach` `GameplayLogicPackageUIData` entry in `m_mods`. The
profile's `UniversalSlotsAndAttachments.GetAttachements()` replacement then
called `ArrayClear(this.m_mods)`, deleting those entries before the tooltip
rendered them. This affected every cyberware item while leaving the ordinary
stat and `localizedDescription` paths intact.

The replacement now preserves `m_mods` and only appends its additional
attachment entries. ArchiveXL's current log already showed the Black Chrome
English package being merged (`All translations merged`), so no new
localization archive or CET/settings layer was necessary. The sanitized source
was synced and compiled at 15:11:33 EDT with `Compilation complete` and a
`final.redscripts.modded` output. A ripperdoc hover of one vanilla and one
Black Chrome implant remains the user-side visual confirmation; the agent did
not launch the game.

The same sync pass removes the previously extracted, inactive Reinforcements
YAML directory from the game-side tree. Repository and game-side active TweakXL
counts now both equal 52, including the new SimpleDroneCompanion payload,
preventing the stale 413/503 warning payload from
returning on the next launch.
